## Overview

The first production release of OmniRepo: a single Go binary that serves
every corporate artifact protocol — OCI/Docker, RPM/YUM, APT/Debian, PyPI,
Helm, RAW blobs, S3 (SigV4) buckets, and Git — on one port, with
embedded React SPA, Trivy-powered vulnerability scanning, project-scoped
access control, and a hard no-outbound-network invariant at runtime.
Target environment is small-to-mid corporate networks and air-gapped
deployments. All 175 v1 requirements shipped.

## Milestone Summary

**Key Decisions:**
- Single Go binary, one port, one volume — all protocols multiplex via chi's `Mount()`; no sidecars.
- Pure-Go SQLite (`modernc.org/sqlite`) with reader/writer split so the image builds `FROM scratch`.
- Embed OCI registry (`google/go-containerregistry/pkg/registry`) and S3 (`gofakes3` + our SigV4 middleware) as `http.Handler`s rather than forking. MinIO explicitly excluded for AGPLv3.
- Trivy runs as a subprocess, never imported as a Go library (dep-tree explosion + unstable API).
- Tailwind 4 + React 19 + Vite 8 + shadcn/ui on the frontend — starting new UI on stable-current versions avoids a forced upgrade cycle.
- Dependency matrix + license summary lives inside README.md (not CLAUDE.md) so the shipped repo is self-contained.
- S3 bucket provisioning is REST/UI, not SigV4 (`gofakes3.CreateBucket` disabled in production); mirrors how AWS console behaves vs API — discovered and closed during the 2026-04-17 walkthrough.

**Issues Resolved During Milestone:**
- All 26 pre-release audit findings (1 Critical, 7 High, 14 Medium, 4 Low) fixed before ship. Header in `AUDIT-FINDINGS.md` was stale ("Nothing fixed yet") despite every item being closed in-code — corrected in commit `e739ea6`, then the file was removed in `add816f` after verification.
- All 15 UI-test findings fixed (P0 repo routing, P1 dashboard search, dashboard clickability, etc.).
- 8 fresh-install walkthrough findings (F-1..F-8) fixed (docker WWW-Authenticate scope, per-repo scan endpoint mount, RPM upload visibility, scan dispatcher handlers for all non-docker kinds, storage widget real-time sum, post-setup banner, breadcrumb dedup, 413/content-type normalization).

**Issues Deferred to v1.1 (tech debt, non-blocking):**
- Docker storage overestimate across shared blobs — dashboard's `repoSizeExpr` fully charges a blob to every referencing repo (N× overcount); intentional for operator mental model, revisit when billing/quota work starts.
- DEB `resolveDebPoolPath` assumes standard Debian pool layout — exotic component/sharding layouts may 404. Handler is defensive (misresolved path → 404, not corruption).
- Codex rescue pass across the 2026-04-17 shipping batch — skipped because the prior Codex invocation hung ~1 h. Worth a time-boxed pass in v1.1.
- 35 checkboxes in the v1 REQUIREMENTS.md were still unticked at audit time — all implemented in code; resolved by this archive flow (see `v1.0-REQUIREMENTS.md`).

**Technical Debt Incurred:**
- `repos.size_bytes` column exists but is never written; dashboard recomputes on read via `repoSizeExpr` (correlated subqueries per repo). Fine at v1 volumes; if dashboards get slow, add a counter-update hook in each protocol's PUT path.
