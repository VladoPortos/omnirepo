<objective>
Redact leaking `%v`-interpolated internals from every `http.Error` call site across the 29 protocol handler files in `internal/protocol/**`. Protocol handlers do NOT emit JSON envelopes (their clients — dockerd, apt, pip, curl, aws-cli, git — don't parse JSON errors) so this plan is purely about stopping the `%v` leak while preserving the protocol-native error shape each client expects. The grep gate in the Makefile prevents future regressions.

Purpose: Closes ERR-03 for the protocol surface. Plan 04 closed it for `/api/v1`; this plan closes it for the other 206 error call sites.

Output: Clean protocol handlers, every real error logged to slog with incident_id, no filesystem paths or driver strings reach clients.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Protocol handler → wire client | Error emitted directly; client (docker, apt, pip, curl) interprets as protocol-native error |
| Protocol handler → slog | Real error logged, keyed by incident_id |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-05-01 | Information disclosure | %v-interpolation of Go error into HTTP response | mitigate | Sweep removes every occurrence; Makefile grep gate prevents regression. |
| T-06-05-02 | Repudiation | No log trail for protocol errors | mitigate | Every redacted site now calls slog.ErrorContext with incident_id and real err; operators can correlate client failures with log entries via the UUID v7. |
| T-06-05-03 | Information disclosure | Wrapped error chain leaking through slog.Any("err", err) | accept | `slog.Any` on err calls Error() which serializes the wrap chain; this is logged server-side only, never sent to client. Operator-visible is correct by design. |
| T-06-05-04 | Denial of service | Excessive slog calls under repeated protocol failures | accept | slog is buffered; volume is bounded by legitimate protocol retries. No additional rate limiting in this phase. |
</threat_model>
