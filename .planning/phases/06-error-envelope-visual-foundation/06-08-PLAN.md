2. Create `scripts/check-contrast.mjs`. The script is a pure-Node utility with no npm deps. It reads `web/src/index.css`, extracts OKLCH values from the `:root` block for every `--status-*` variable, converts each to sRGB via the standard Oklch→OKLab→linear sRGB→sRGB pipeline, computes WCAG relative luminance, and derives contrast ratios.

Structure (pseudo — implement in real JavaScript):

- `import { readFileSync } from 'node:fs'` and read `web/src/index.css`
- Parse the `:root` block (regex): extract `--(name): oklch(L C H)` triplets into a map
- Define helpers:
  - `oklchToOklab({L, C, H})` → `{L, a, b}` (convert polar to cartesian using trig)
  - `oklabToLinearSrgb({L, a, b})` → `{r, g, b}` (Bottosson OKLab matrix: see https://bottosson.github.io/posts/oklab/)
  - `linearToSrgb(c)` → number (gamma companding: `c <= 0.0031308 ? 12.92*c : 1.055*(c**(1/2.4))-0.055`; clamp to [0,1])
  - `relativeLuminance({r,g,b})` → number (WCAG formula: `0.2126*R + 0.7152*G + 0.0722*B` where each channel uses the piecewise `<=0.03928 ? c/12.92 : ((c+0.055)/1.055)**2.4` transform)
  - `contrast(l1, l2)` → `(max+0.05)/(min+0.05)`
- Iterate the six statuses (`healthy`, `warning`, `failure`, `disabled`, `maintenance`, `neutral`)
- For each: compute luminance of fill and foreground, derive ratio, print formatted row
- Track a `failed` boolean; if ANY text/fill ratio < 4.5, set failed
- Final output: table-style rows, summary PASS/FAIL; call `process.exit(failed ? 1 : 0)`

The complete verbatim implementation is in RESEARCH.md §Q10 and PATTERNS.md "scripts/check-contrast.mjs" — executors should copy that code and adapt import paths to the repo layout.
