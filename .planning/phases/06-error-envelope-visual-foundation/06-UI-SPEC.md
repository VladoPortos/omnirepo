# Phase 6 — UI Design Contract

> Visual and interaction contract for the v1.1 foundation phase. Generated by gsd-ui-researcher. Downstream consumers: gsd-planner (writes plan tasks against this), gsd-executor (implements), gsd-ui-checker/auditor (verifies).
>
> This phase establishes the **stable API error envelope** and the **shared design-system primitives** that every later v1.1 phase (7 SNIPPET/EMPTY, 8 FAV, 9 HEALTH, 10 OVERVIEW) renders on top of. It does NOT replace the shadcn/base-ui + Tailwind 4 baseline already shipped in v1.0; it formalises and **extends** it so downstream phases consume one source of truth instead of re-inventing tokens per surface.
>
> Tokens declared here must survive into v1.2+ without rename — downstream phases type against them.

## Spacing Scale

Declared values (multiples of 4, using the Tailwind 4 default spacing scale — DO NOT introduce custom spacing tokens in this phase):

| Token | Tailwind class | Value | Usage |
|-------|----------------|-------|-------|
| xs | `gap-1`, `p-1` | 4px | Icon-to-label gaps inside badges and buttons |
| sm | `gap-2`, `p-2` | 8px | Compact element spacing, table-cell padding |
| md | `gap-3`, `p-3` / `gap-4`, `p-4` | 12 / 16px | Default element spacing; code-block padding is 12px; card body padding is 16px |
| lg | `p-6` | 24px | Card section spacing, dialog body padding |
| xl | `p-8` | 32px | Page-level padding (already used by `AppShell` `<div className="p-8">`) |
| 2xl | `gap-12` | 48px | Major section breaks inside a page (e.g. between "Latest artifacts" and "Recent uploads" on Overview) |
| 3xl | `py-16` | 64px | Empty-state vertical padding (full-panel empty states only) |

**Page layout grid:** pages authored for 1366×768 and 1440×900 (see Responsive Behavior). Inner content area below sidebar clamps to `max-w-7xl` (1280px) when page body is a single column; full width when a table or dashboard grid occupies the viewport.

**Card radius:** `rounded-lg` (uses `--radius: 0.625rem` from `:root`).
**Code-block radius:** `rounded-md` (matches existing `SnippetPanel` pattern).
**Badge radius:** `rounded-4xl` (pill — already in baseline `badge.tsx`).

Exceptions:
- Copy-to-clipboard icon button inside a pre block uses `absolute right-1.5 top-1.5` (6px inset) in the v1.0 `SnippetPanel` — documented precedent that Phase 6 preserves when reusing that exact panel. **Scope limit (grep-verifiable):** Phase 6+ **new** copy-button placements MUST use 8px (`right-2 top-2`). The 6px carve-out applies ONLY to the existing v1.0 `SnippetPanel.tsx` file being reused as-is, not to any new placement or new file. The planner is expected to write an acceptance test that greps new files for `right-1.5` / `top-1.5` and fails if they appear outside `SnippetPanel.tsx`.
- Horizontal scroll threshold for dense admin tables: sticky first column is allowed; whole-page horizontal scroll is forbidden at 1366×768.

## Typography

Exact values. Phase 6 formalises the scale; downstream phases use these class names verbatim.

**Sizes declared: 4 (12, 14, 18, 24 px). Weights declared: 2 (400 regular, 600 semibold).** No other sizes or weights are permitted in Phase 6+ code. The checker greps new code for disallowed classes.

| Role | Tailwind class | Size | Weight | Line Height | Usage |
|------|----------------|------|--------|-------------|-------|
| Heading 1 | `text-2xl font-semibold tracking-tight` | 24px | 600 | 1.2 (leading-tight) | Page titles on dashboard/health/overview landing AND primary page heading. (Previously had a separate 30px "Display" role — merged into H1. `tracking-tight` is the differentiator when a designer wants the "hero" feel on top-of-page headings.) |
| Heading 2 | `text-lg font-semibold` | 18px | 600 | 1.3 | Card titles, dialog titles, sub-section headings |
| Heading 3 | `text-sm font-semibold` | 14px | 600 | 1.3 | Sub-card / section labels, table group rows |
| Body | `text-sm` | 14px | 400 | 1.5 (leading-normal) | Default paragraph / body text |
| Label | `text-xs font-semibold` | 12px | 600 | 1.4 | Table headers, form labels, metric-tile labels, badge text |
| Metadata | `text-xs text-muted-foreground` | 12px | 400 | 1.4 | Timestamps, actor attributions, "last scanned" strings |
| Code/Mono | `font-mono text-xs` | 12px | 400 | 1.5 | Snippet bodies, digests, version strings, CLI commands |
| Display-mono | `font-mono text-sm` | 14px | 400 | 1.5 | Inline code inside body text (e.g. `rpm.repo` path in guidance copy) |

**Weights used: 400 (regular) and 600 (semibold) only.** No 300, 500, or 700. Rationale: `web/src/index.css` loads exactly two static Inter `.woff2` files (400 and 600). Using `font-medium` (500) against static files would render as a browser-picked nearest match (typically 400 on static-only setups), which is visually deceiving and fragments the type voice. Downstream phases MUST NOT introduce `font-medium` (500), `font-bold` (700), or `font-light` (300). The checker greps new Phase 6+ code for any such class and fails the phase if found.

**Line height rules:** body + code = 1.5; headings = 1.2–1.3; no headings below 14px.

**Tracking:** `tracking-tight` on `Heading 1` (24px) only. Default elsewhere.

**Size scale rationale:** 4 sizes is deliberately tight. The v1.0 admin UI already lives comfortably within `text-xs` / `text-sm` / `text-lg` / `text-2xl`; dropping a fifth step (previously 30px / `text-3xl`) removes cross-phase drift where HEALTH and OVERVIEW page titles might otherwise pick a different size than the rest of the shell. `tracking-tight` on H1 is the cosmetic knob for "hero feel" without adding a new size step.

## Copywriting Contract

### Error envelope class → UI treatment (ERR-01..ERR-07)

The canonical envelope (ERR-01) is:

```typescript
interface ApiErrorEnvelope {
  code: string;          // stable machine identifier, e.g. "repo.not_found", "validation.required_field"
                         // MUST match /^[a-z][a-z0-9_]*\.[a-z][a-z0-9_]*$/
  message: string;       // human, single sentence, present-tense, no internal paths
  hint?: string;         // optional single-sentence remediation ("Try again in a few seconds.")
  class: "validation" | "permission" | "transient" | "operator_action_required";
  incident_id?: string;  // ULID/UUID correlating UI ↔ server log ↔ audit; present when server logged it
  details?: {            // optional class-specific payload
    field?: string;      // validation class: which form field failed (dot-path allowed: "repo.name")
    retry_after_ms?: number;  // transient class: suggested wait before Try-again
    operator_route?: string;  // operator_action_required class: UI path e.g. "/admin/trivy"
    operator_label?: string;  // operator_action_required class: CTA label e.g. "Go to Admin → Trivy"
  };
}
```

OpenAPI 3.1 fragment (MUST be added to `web/openapi.yaml` or the server-side spec source) — this is the contract that `oapi-codegen` generates types from and the UI type imports:

```yaml
components:
  schemas:
    ApiErrorEnvelope:
      type: object
      required: [code, message, class]
      additionalProperties: false
      properties:
        code: { type: string, pattern: "^[a-z][a-z0-9_]*\\.[a-z][a-z0-9_]*$" }
        message: { type: string, maxLength: 280 }
        hint: { type: string, maxLength: 280 }
        class:
          type: string
          enum: [validation, permission, transient, operator_action_required]
        incident_id: { type: string, maxLength: 64 }
        details:
          type: object
          additionalProperties: true
          properties:
            field: { type: string }
            retry_after_ms: { type: integer, minimum: 0 }
            operator_route: { type: string }
            operator_label: { type: string }
```

**Existing `ApiError` (web/src/api/client.ts) MUST be migrated in this phase** — it currently carries `{status, code, detail}` with a `{error, detail}` wire shape, which is incompatible. Migration plan: keep the `ApiError` class, add `message`/`hint`/`class`/`incidentId`/`details` fields, and update `handleResponse` to parse the new envelope. Server handlers that still return `{error, detail}` during the migration window return envelopes too; no dual-read path.

### Tone rules
- **Never blame the user** for transient or operator-action-required classes.
- **Never leak internal detail** in `message` or `hint` — no filesystem paths, no driver/library strings, no stack traces (ERR-03). The server logs those against `incident_id`.
- **One sentence per field.** If it needs two sentences, the second goes in `hint`.
- **Active voice, present tense.** "The Trivy DB is missing" not "The Trivy database has been found to be missing".
- **Use product nouns exactly once per message.** "This repository cannot be deleted" not "This repo cannot be deleted".
- **No emoji. No exclamation marks except on copy confirmations ("Copied!").**

## Interaction Patterns

### Loading → data → error state machine

Every data-bearing surface has three visual states the renderer MUST cover:

| State | Visual | Persistence rule |
|-------|--------|------------------|
| `loading` (initial, no cached data) | Corresponding Skeleton* component with `role="status" aria-label="Loading"` | Shown for any load >200ms; shorter loads render nothing to avoid flash |
| `loading` (re-fetch with cached data) | Existing data, muted overlay (`opacity-60 pointer-events-none`) with a small `RefreshCw` spinner in the top-right of the container | 300ms+ |
| `success` | Real content | — |
| `error` | `ErrorEnvelopeRenderer` inline mode inside the container | Replaces the container body; container chrome (card border, title) stays so surrounding layout doesn't shift |
| `empty` (success, zero rows) | Phase-7-owned EmptyState — Phase 6 just leaves the slot |

### Copy-to-clipboard

- Trigger: any `CopyButton` or `CopyInline` instance. Existing `CopyButton` has fallback for non-secure contexts (textarea + `execCommand`) — keep.
- Confirmation: tooltip text swap to "Copied!" + icon swap `Copy` → `Check` (text-green-500) for 2000ms. No toast (toast is redundant with tooltip, and HEALTH/OVERVIEW surfaces chain multiple copies quickly).
- A11y: trigger has `aria-label="Copy to clipboard"` (or specific like `"Copy pip install command"` when contextual); after copy, a polite `aria-live="polite"` announcement (the icon/tooltip swap is not enough for SRs) — this is a Phase 6 improvement over the v1.0 `CopyButton`, which must receive an `aria-live` region addition.
- Keyboard: focusable, Enter or Space triggers.

### Retry affordance (ERR-04)

- `transient` class renders a `<Button variant="outline" size="sm">Try again</Button>` bound to the TanStack Query `refetch` function.
- If the envelope carries `details.retry_after_ms`, the button disables and shows `"Try again in {N}s"` counting down, then re-enables.
- Retry MUST NOT re-invoke any form state — it replays the last request only.
- Retry never appears for other classes (validation/permission/operator-action-required).

### Field-level validation (ERR-06)

- `ErrorEnvelopeRenderer` with `class: "validation"` + `details.field: "foo.bar"` surfaces:
  1. A global summary message at the top of the form ("Some fields need your attention.")
  2. An inline per-field message under the matching input, rendered via a `FieldErrorSlot` sub-component, in `text-xs text-destructive`.
  3. `aria-invalid="true"` + `aria-describedby` wiring from input to the slot.
- Form libraries are not chosen here — whatever wiring the consumer uses, the renderer exposes a `fieldErrors: Record<string, string>` prop for the form to consume.

### Operator deep-link (ERR-05)

- `operator_action_required` errors render the operator CTA inline as a `<Button variant="default" size="sm">` (primary voice — this is the single allowed primary CTA for an error surface).
- `details.operator_route` is a UI path (`/admin/trivy`), never an external URL (air-gap invariant).
- If `details.operator_label` is absent, use the default-by-code-prefix table (see Copywriting contract).

### Incident ID correlation (ERR-07)

- When `incident_id` is present, render at the bottom of the error block:

```
Incident 01JSV8R2...  [Copy]
```

- Clicking the Copy button copies the full ID. This is the value the user gives an operator for log correlation.
- Never render `incident_id` if the server omits it (absence is meaningful — it means the server didn't log it).

### Button hierarchy (VISUAL-05)

One page surface may have:
- At most **one** `default` (primary) button per logical scope (page, card, dialog).
- Any number of `outline` (secondary) buttons.
- `ghost` for tertiary / icon-only (e.g. copy, close).
- `destructive` **only** for actions that permanently delete or disable. A destructive button MUST be paired with a Dialog confirmation that has `Cancel` focused by default.
- `link` for inline text links only — never for page-level CTAs.

Primary vs destructive visual distinction (VISUAL-05) is already guaranteed by the baseline:
- `default` → near-black fill, white text (`bg-primary text-primary-foreground`)
- `destructive` → red-tinted fill (`bg-destructive/10 text-destructive`)
These are NOT visually adjacent and MUST NOT be restyled in downstream code.

### Focus / keyboard

- Every interactive element uses the baseline `focus-visible:ring-3 focus-visible:ring-ring/50` — never a custom ring.
- Dialogs trap focus (base-ui handles this).
- Esc dismisses dialogs and sheets.
- "Try again" button keyboard Enter triggers retry.

## Responsive Behavior (VISUAL-06)

Target resolutions: **1366×768** (minimum) and **1440×900** (comfortable). No mobile/tablet breakpoints.

### Layout envelope

- Sidebar is always-on at ≥1024px (Tailwind `lg`). The existing `AppSidebarProvider` handles collapse behaviour below that threshold (unused in v1.1 but must not regress).
- Main content min-width at 1366: the sidebar is ~256px; main column therefore ≥ 1110px. Designs MUST fit in 1110px without horizontal scroll.
- `AppShell` wraps main content in `p-8` (32px) — content usable width at 1366 is `1366 - 256 - 64 = 1046px`.
- Content max-width (single-column pages) is `max-w-7xl` (1280px) — at 1440, this leaves balanced margins.

### Table overflow policy

Admin tables (projects/repos/artifacts/audit/users/tasks/trash) use one of:
1. **Sticky first column + horizontal scroll inside the table body only** (never the page). `overflow-x-auto` on a wrapper; `position: sticky; left: 0; background: var(--card);` on the first `<th>/<td>`.
2. **Column chooser** (deferred to v2.0 per `improvements.md` — NOT Phase 6).
3. **Responsive column hide**: secondary-priority columns get `hidden lg:table-cell` so they disappear only below 1024, where we don't ship. In practice this is unused at 1366+.

Phase 6 picks option 1 for the tables that already exist (projects/repos/artifacts/audit) and adds a Playwright test at 1366×768 that asserts `document.documentElement.scrollWidth <= document.documentElement.clientWidth` on every admin route.

### Dashboard grid (HEALTH/OVERVIEW — they use Phase 6 primitives)

- HEALTH cards: 3-column grid at ≥1280px, 2-column at 1024–1279px. Phase 6 does not implement the dashboard — it only declares that `SkeletonCard` width goes to `100%` inside a grid cell.
- OVERVIEW cards: 2-column grid primary section + 1-column secondary section, matches HEALTH pattern.

### Dialog/sheet sizing

- `Dialog`: `max-w-lg` default (32rem), `max-w-xl` for forms, `max-w-2xl` for impact-preview destructive confirmations with detail.
- `Sheet` (used by `SnippetPanel`): `right` side, `w-full sm:max-w-md` already in baseline. For `OVERVIEW` / `HEALTH` use `max-w-lg`.

### Breakpoints used
- `sm` 640, `md` 768, `lg` 1024, `xl` 1280, `2xl` 1536 (Tailwind defaults, unchanged).
- Phase 6 targets the `xl` breakpoint (1280+) as the comfortable layout.
